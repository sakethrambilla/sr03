## Deviations
- T1: `withUncommitted`'s early path returns `[...commits]` — required by the `readonly` parameter.
  Verified by diff that this and the signature are the ONLY changes to the moved logic; the
  `layoutGraph` body is byte-identical.
- T1: the plan claimed the lane layout was recomputed per keystroke. **It was not** — the memo
  already existed and `filterText` was never a dependency. Spec and plan were corrected before
  execution; only `visibleRows` and `edges` actually needed memoizing.
- T1: the pinning array was generated by running the shipped algorithm, not by reading it. That
  immediately caught a hand-written lane guess (`[0,0,1]` vs the real `[0,0,0]`), which is the
  method earning its keep.
- T2: `laneCount` and `height` are computed in the panel and passed into `Graph` as props — the row
  and header `paddingLeft` must equal the SVG width, and both must come from one
  `getTotalSize()` rather than two independent computations.
- T2: SVG gained `pointer-events-none`. It is now an absolute overlay across the rows' left
  padding; without it the leftmost strip of every row would stop responding to clicks.

## Known visual change — the spec's "no-op" constraint does not fully hold
The old layout had a **real misalignment**: the SVG sat in a flex sibling wrapped in `py-1`, so its
row 0 was at +4px while the table's row 0 sat below a 40px header — roughly a 36px offset between a
node and the commit it describes. Anchoring both to one container removes that. So a before/after
screenshot will NOT be pixel-identical in the graph column, and that difference is the fix.
