# Plan — settings tabs, richer appearance, Codex fixes

Spec: [spec.md](./spec.md)

## Goal

Three deliverables, each independently shippable:

1. The Providers settings section becomes a tab strip — one provider's card at a time.
2. Appearance gains 12 bundled interface fonts, 12 bundled code fonts, and 6 new themes.
3. Three confirmed Codex adapter defects are fixed.

## Constraints

Repo conventions that bound every task below — from `CLAUDE.md`:

- **Server TS is type-stripped, not compiled.** `erasableSyntaxOnly` is on: no parameter
  properties, no enums, no namespaces. Server imports use explicit `.ts` extensions.
- **UI comes from shadcn/ui.** Never hand-roll a tab strip, button, dialog or select. Add
  components with `pnpm dlx shadcn@latest add <name>`, run inside `web/`.
- **`web/src/components/ui/*` is generated output.** Restyle through tokens or a wrapper in
  `components/ui.tsx` — never edit those files.
- **Colors are the shadcn token set only.** Defined in `web/src/index.css`. No raw hex, no one-off
  `oklch` outside a theme block.
- **Radii:** `rounded-md` for interactive, `rounded-lg` for panels, `rounded-full` only for dots.
- **Zustand selectors must never return a fresh object or array.** An inline `?? []` causes an
  infinite render loop; use a module-level empty constant.
- **`server/src/types.ts` and `web/src/lib/types.ts` are mirrored by hand** and change together.
- **Comments only where the code can't speak for itself.**
- `@/` resolves to `web/src`.

## Verification commands

Every task's verification uses one or more of these, run from the repo root:

```bash
pnpm typecheck     # tsc --noEmit, both packages — must exit 0 with no output
pnpm test          # server then web, as two separate runs
pnpm dev           # server :3399 + Vite :5399 — open http://localhost:5399
```

**`pnpm test` prints two summaries, not one.** It runs `pnpm -C server test && pnpm -C web test`,
so the output ends with two `ℹ tests` / `ℹ pass` / `ℹ fail` blocks. The baseline as of 2026-09-22:

| Package | tests | pass | fail |
|---|---|---|---|
| server | 60 | 60 | 0 |
| web | 51 | 51 | 0 |

There is never a single combined number. A task that adds tests raises exactly one of these two;
each task below says which. `fail 0` in **both** blocks is the bar.

Manual provider verification uses a scratch repo, never a real project:

```bash
mkdir -p /tmp/sr03-repo && cd /tmp/sr03-repo && git init -q -b main \
  && echo hello > README.md && git add . && git commit -qm init
```

## Notes for the implementer

- **`@fontsource-variable` vs `@fontsource`.** Four families have no variable build and must use
  the static package: `ibm-plex-mono`, `iosevka`, `space-mono`, `commit-mono`. The other twenty use
  `@fontsource-variable`. Getting this wrong fails the install, not the build. Verified against the
  npm registry on 2026-09-22; all 24 resolve at `5.3.0`.
- **The installed-font probe must not gate bundled fonts.** `installed()` measures a candidate
  against a generic and rejects anything that matches. A bundled face that has not finished loading
  measures as missing, so bundled families are listed unconditionally and never passed through the
  probe.
- **Theme token blocks carry exactly 20 custom properties**, matching the existing `zinc` block:
  `--background --foreground --card --card-foreground --popover --popover-foreground --primary
  --primary-foreground --secondary --secondary-foreground --muted --muted-foreground --accent
  --accent-foreground --destructive --destructive-foreground --border --input --ring --faint`.
  `--added` is **not** among them — it is an editor semantic defined once at `:root` and
  deliberately not redefined per theme. Omitting a property inherits the base palette and is a bug,
  not a shortcut.
- **`ProviderLogo`** in `web/src/components/ProviderLogo.tsx` already carries brand marks for all
  three providers, keyed by `ProviderId`, filled with `currentColor`. Use it for the tab strip —
  do not draw new glyphs.
- **`STATE_STYLE`** at `web/src/components/SettingsView.tsx:31` maps provider state to a dot class
  and label. Reuse it for the tab's state dot rather than defining a second mapping.
